## Independent display filters and clean measurement CSV

Settings provides independent ECG and PPG display filters. Both offer Raw bypass and optional high/low-pass filters; ECG additionally has an independent 50 Hz notch. ECG extra HP: Off / 0.5 / 1 Hz; extra LP: Off / 20 / 30 / 40 Hz. PPG HP: Off / 0.1 / 0.3 / 0.5 / 1 Hz; LP: Off / 2 / 3 / 4 / 5 / 8 / 10 / 20 Hz. Defaults remain ECG extra HP Off, LP 40, notch ON, mV, +/-1 mV; PPG defaults to Filtered with 0.5 Hz HP and 3 Hz LP. Only IR is plotted; Red is still acquired, independently filtered and exported. Chip ECG 0.5-40.96 Hz, ECG 256 SPS, PPG 100 SPS, gain and sensor configuration are unchanged. Raw disables extra GUI processing; it cannot undo the chip filters. Calibration always bypasses GUI filters. Switching a display choice reprocesses only its own plotted buffer, without changing stored raw measurements or restarting acquisition.

Causal second-order high/low-pass and Q=10 notch sections use the [W3C/RBJ coefficients](https://www.w3.org/TR/audio-eq-cookbook/). DC-primed independent Red/IR states avoid startup pulses/cross-channel mixing. ECG/PPG have 1 s / 2 s raw warmup views, not a physiological validity guarantee. Gaps and invalid PPG reset state. Raw DC and filtered AC PPG points are never combined on one axis. Filters change morphology/phase; they do not establish optical/physiological accuracy.

Save CSV recomputes the selected ECG and PPG filters over the **complete stored raw recording**, using the choices at export time. The result does not mix different settings chosen earlier in the session. Temperature exports surface and ambient values without additional filtering. Each row holds one original channel sample; other channels' cells are blank. No samples are interpolated, padded, averaged into a shared cadence or zipped by index. Rows are sorted by session/device time; each channel's original device microseconds and sample index are retained. Raw and filtered values share the same input timestamp; causal filter delay is not compensated. These timestamps are estimated from the device sample clock, not BLE arrival time or calibrated hardware synchronization. A sequential session column distinguishes reconnect/reboot clock epochs.

Filtered cells are blank during bypass, warmup, internal calibration or hard-invalid processing; no zero values are invented. `ecg_input` distinguishes electrodes from internal calibration. `ecg_filter` and `ppg_filter` identify the processing used. CSV contains no protocol flags, FIFO word/tag, validity/verification fields, boot ID, registers, status or error/fault messages; unverified R-R diagnostics are omitted. Raw signed ECG, nominal input mV, Red/IR counts and temperature remain unmodified. [Complete CSV column contract](../VNS_TX_nRF/docs/PROTOCOL.md#csv). Earlier verification CSVs use their historical format and are not rewritten.

3. In Control → Acquisition, Start requests independent sensor acquisition and Stop stops all streams. A missing/failed PPG no longer blocks ECG and temperature when the updated TX firmware is installed. Sensor faults are shown in Control; advanced counters and raw ECG diagnostics are collapsed in Settings. Change LED current codes only while stopped. The plotted window is 4, 8 or 12 seconds; changing it does not change sensor sample rates.
4. ECG defaults to **Monitor 0.5-40 Hz, 50 Hz notch ON, input mV, fixed +/-1 mV** (the user's current settings saved on 2026-11-02). The waveform window defaults to 8 seconds. Settings -> ECG Input & Display selects Raw/Filtered, independently selects extra high/low-pass and ECG 50 Hz notch, selects mV/Counts and Auto/fixed ranges, and reads/saves actual register logs. The default filtered ECG view uses the normal sensor's 0.5 Hz HP and an additional second-order 40 Hz LP; Raw still includes the chip's configured filters. Internal calibration always bypasses GUI filters. Unknown-gain legacy data remains Counts only. Both ECG/PPG use device sample time, with visible gaps. ECG is always a solid red trace, including unverified samples; styling does not change the source validity flags or authorize HRV computation. Auto Scale does not validate the signal; a fixed range can clip displayed data; the raw measurements and diagnostics remain available. No mock or simulated data is displayed.
   Stop before applying Gain 80 / Electrodes or internal 0.5/1 mVpp. Calibration is explicitly NOT HUMAN ECG, requires electrodes removed, and inhibits wireless power. Read actual registers after Start; a stopped device deliberately has ECG OFF and both inputs open. As of 2026-11-02, Gain 160 is manually available while stopped without a prior Gain 80 run. The firmware and input selector now default to Gain 160 at 256 SPS. Electrodes input is the startup source; Red/IR LED codes remain 31/31. See [the complete calibration procedure and expected registers](../VNS_TX_nRF/docs/VALIDATION.md).
5. Control → Power ON controls XKT only and renews a three-second firmware lease. OFF, disconnection, faults and hidden-page handling release it. Boost remains wired ON. The display reports the enable command, not measured RF power.
6. Clear Data clears local records/plots; it does not reset the device. Save CSV exports original captured measurements. The new clean measurement schema carries raw and filtered ECG/PPG plus temperature, independent device timestamps and processing labels. Calibration input is explicitly labelled; debug and validity/error fields are omitted. Recording stops adding rows at 200,000 and displays a warning; plots continue. Save before reloading.

SpO2 Est shows a quality-gated, uncalibrated optical estimate after a continuous 10 s paired Red/IR window. HR and HRV are now prototype ECG-derived estimates calculated by the independent browser analyzer described below. Unverified firmware R-R remains unused and is not exported. Temperature is surface/ambient, not calibrated core body temperature.

Bring-up uses a manual connection flow: click **Connect**, select **VNS_TX_01**, and wait for **Connected**. The app does not restore a saved device, reconnect automatically, retry failed connections, or send background status queries. Firmware status notifications keep the display updated; Settings → Refresh explicitly requests GET_STATUS. After a disconnection, click Connect again. Repeated Connect clicks cannot create concurrent attempts.

Sensor faults remain visible but do not prevent a valid BLE connection. The new firmware keeps healthy sensors recording when another sensor fails; wireless power stays inhibited while any fault is present. Temperature freshness follows device sample/status time, independently of PPG. Start, Power and configuration commands are never replayed. A timed-out command disconnects because its outcome is uncertain. In-memory records survive manual reconnects and retain boot and connection IDs. No measurements are uploaded to any server. The connection flow is unchanged. Independent sensor acquisition requires rebuilding/flashing the updated TX firmware. Older firmware is still decoded, but the fault message asks for a firmware update instead of promising partial acquisition.

### SpO2 prototype method and limits

`src/data/spo2.ts` uses paired raw Red/IR from the same FIFO sample, independent of selectable display filters. Red and IR are sequential optical slots in the sensor's sample, not physically simultaneous exposures. Confirmed LED codes are attached from the device status before recording. Unknown/off LEDs, any invalid/clipped sample, time/index discontinuity or LED-code change resets the whole window. A new current needs a fresh continuous 10 s window.

Analysis updates every 100 samples. Fixed 0.5–5 Hz preprocessing locates pulses after discarding 2 s startup; raw five-point-smoothed values supply each beat's AC and linearly interpolated valley DC. It computes `R=(AC_red/DC_red)/(AC_ir/DC_ir)` for matched cycles. Engineering quality gates require DC in 5000–250000 counts, <5% start/end DC drift, raw excursion <30% of DC, Red/IR correlation ≥0.90, a common 40–180 bpm period with both autocorrelations ≥0.70, ≥3 matched cycles, per-channel normalized pulse amplitude 0.1–20%, peak alignment within 100 ms and stable ratios (relative MAD ≤10%, ≥80% within 20% of the median). These are prototype rejection thresholds, not manufacturer performance guarantees or comprehensive motion compensation.

The illustrative mapping `SpO2 = 104 − 17R` comes from [ADI UG6409, pp. 30–31](https://www.analog.com/media/en/technical-documentation/user-guides/max3010x-ev-kits-recommended-configurations-and-operating-profiles.pdf). Results outside 70–100% are blank, never clamped to plausible saturation values. Failed windows clear the estimate, and data expires after 3 device seconds without a fresh window. The UI explicitly says **SpO2 Est**. This example mapping is not a calibration of this board, finger contact, LED/PD geometry or optical enclosure. [ADI's MAX30102 FAQ](https://ez.analog.com/optical_sensing/a/documents/c/max30102efd-t-faq/DO19495/does-the-max30102-have-an-r-curve-associated-with-it-to-correlate-the-ratio-r-acred-dcred-acir-dcir) states that the device has no universal associated R curve; [ADI's calibration guidance](https://www.analog.com/en/resources/technical-articles/guidelines-for-spo2-measurement--maxim-integrated.html) explains the need for whole-system calibration. Accuracy and low-saturation performance are unverified; do not treat this estimate as a medical measurement.

Software evidence: [76 tests](verification/csv-led-spo2-tests-2026-11-02.log) and [TypeScript/Vite build](verification/csv-led-spo2-build-2026-11-02.log). ## Monitor / Control and ECG-derived HRV — 2026-11-02

Monitor uses four equal-area cards: solid red ECG, IR PPG, surface temperature and HRV RMSSD. Narrow displays stack four rows; at 768 px and wider the grid is 2 × 2. Monitor omits device status, sample rate, filter captions and last-received-data text. The PPG plot scales from IR only. ECG/PPG retain the selected 4/8/12 s window; temperature shows 60 s and HRV shows 300 s of device time. No trend interpolation, mock data, hidden validity overrides or sample-rate changes are introduced. Start/Stop/Clear/Save and LED controls move into Control → Acquisition. Settings keeps filter/input controls, with register/Bluetooth diagnostics collapsed and long descriptions removed.

`src/data/hrv.ts` runs independently of all display choices on raw, gain-tagged, valid electrode ECG at 256 SPS. It adapts the [Pan–Tompkins QRS-detection approach](https://pubmed.ncbi.nlm.nih.gov/3997178/): 5–18 Hz biquad band-pass and 50 Hz notch, five-point derivative, squaring, 38-sample (~148 ms) integration, 2 s threshold learning, adaptive energy/amplitude thresholds, 250 ms refractory period and slope-based T-wave rejection under 360 ms. Candidate maxima are consolidated; the local absolute raw extremum near the band-passed peak supplies the original device timestamp. The causal detection latency is about 0.3 s. This is an adaptation, not an exact reproduction: it does not implement the original search-back stage. The missing-beat interval is rejected rather than reconstructed.

R-R intervals outside 300–2000 ms, intervals >20% from the recent accepted median, and low signal/noise ratios are excluded. Three consecutive accepted intervals are needed for HR; it uses the last five accepted intervals' median. HRV computes `sqrt(mean((RR[i]-RR[i-1])²))` in milliseconds over the last 60 s, using only adjacent accepted pairs. It requires ≥30 s span, ≥20 accepted intervals, ≥90% accepted coverage and three current accepted intervals. Rejected beats are never bridged or interpolated. Invalid/clipped/calibration/unknown-gain or source samples, sample/index/time gaps and gain changes reset analysis. Live estimates expire after 3 device seconds without a good interval; Stop/disconnect resets the analyzer. Blank values indicate insufficient or rejected input.

The [HRV Task Force standard](https://pubmed.ncbi.nlm.nih.gov/8598068/) defines clinical HRV in terms of normal-to-normal intervals. This implementation screens RR timing and signal quality but does **not** validate sinus origin or classify ectopic beats. Its 30–60 s rolling RMSSD is a prototype estimate, not a standard five-minute clinical HRV test or a validated medical-grade result. Do not use it for diagnosis, treatment or stimulation decisions. Changing display filters does not change the analysis channel. Measurement CSV now includes ECG-derived HR and RMSSD at the original R-peak sample timestamps, plus optical SpO2 estimates at PPG window-end timestamps, as described below.

Verification: [70 software tests PASS](verification/monitor-hrv-tests-2026-11-02.log), TypeScript/Vite production build PASS. Tests include known RMSSD values, exclusion without bridging, positive/inverted synthetic QRS with T waves and 50 Hz interference, variable RR, flatline, missed/extra beats, invalid/calibration input and gap resets. Fixtures are numerical tests only, never shown as real measurements.

A reproducible offline [single-record benchmark](verification/hrv-benchmark-100-2026-11-02.json) uses the full public [MIT-BIH record 100 MLII](https://physionet.org/content/mitdb/1.0.0/) with linear 360→256 SPS resampling. Excluding the first 5 s and matching one-to-one within ±150 ms: 2266 true positives, 0 false positives, 1 false negative; sensitivity 99.956%, positive predictivity 100%. Median/p95 absolute peak timing errors are 1.475/3.993 ms; matched RR RMSE is 2.321 ms. [Benchmark script](verification/hrv-benchmark.ts) reads official WFDB 212/annotation formats and records input hashes. This checks one favorable reference record, not the full database, NN/ectopic classification, noisy dry electrodes or MAX30003 hardware. It cannot establish clinical performance. No public ECG was injected into the running app, and no new live acquisition or firmware build/flash was performed.
